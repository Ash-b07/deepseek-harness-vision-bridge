# 1.0 Preview 已知问题

## 1. 上传图片可能在多轮会话中被重复识别

上传适配器会检查完整消息历史。历史图片仍以图片块存在时，后续 `stream()` 可能再次调用视觉模型。

影响：额外延迟、额外 token/费用，以及免费视觉模型更容易出现 429。

计划：让上传适配器和工具桥共享图片指纹缓存，并增加“同一历史图片连续多轮只调用一次”的测试。

## 2. 只有一个视觉后端

当前配置只有一组 `visionProvider + visionModel`。429、超时或服务故障不会自动切换备用模型。

## 3. `read_image` 兜底会显示红色

这是当前工具输出协议的折中。桥接描述仍会放进工具结果内容，但 UI 会把它显示为失败调用。正常路径是显式使用 `vision_bridge`。

## 4. 上传图片需要使用 `vision-bridge` 路由

直接使用 `deepseek-official` 时，图片会在插件运行前被能力预检拦截。可以在模型选择器中选择桥接路由，或把它设为默认模型。

## 5. 失败可能中断当前轮次

上传适配器在视觉模型失败时会抛出错误。1.0 还没有“所有视觉模型失败后仍让 DeepSeek 返回正常文本”的降级路径。

## 6. 依赖 Harness 内部扩展接口

当前版本针对 DeepSeek Harness `0.1.0-rc.6` 的本地接口完成验证。后续 Harness 版本可能改变工具分发、附件或 LLM 适配器行为。
